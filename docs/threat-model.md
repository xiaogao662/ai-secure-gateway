# 威胁模型：AI Secure Gateway

适用范围：当前本机、虚构数据、只读工具的演示版本。威胁模型就是事先说明攻击者能做什么、系统保护什么，以及哪些假设一旦失效，结论就不再成立。本文描述设计边界，不是完整安全审计证明。

## 1. 要保护什么

- 材料正文：未经授权的账户不能获得全文，也不能获得其中一句话。
- 材料列表：编号和标题也按照当前账户权限筛选；它们在数据库中并未加密。
- 身份与权限：身份以服务器端会话为准；学生仅访问自己的材料，导师访问已分配学生的材料，管理员可访问所有材料。
- 加密密钥、模型 API 密钥、会话凭证和密码：不能因工具输出、错误或审计记录而暴露。会话凭证是浏览器登录后用来证明身份的随机值。
- 审计记录：保留调用者、目标、结果和请求编号，供管理员追查；不声称日志不可篡改。

## 2. 攻击者与可信前提

主要攻击者是已登录但没有目标材料权限的用户，也考虑未登录访问。攻击者可以修改消息、请求字段、工具名称和参数，猜测材料编号，声称自己是管理员或已经得到他人同意。测试中人工构造工具调用，是模拟模型输出完全不可信的情况，不是给客户端开放任意函数执行入口。

假设后端代码、运行进程、服务器操作系统、数据库权限关系及密钥配置未被攻击者控制，且有效的高权限会话未失窃。AI 输出不属于可信前提：即使它提出越权调用，也应受到后端限制。

这里的“可信”不是说组件没有漏洞，而是本轮设计依赖这些组件正确运行；服务器被攻破时，网关不提供独立的进程隔离防线。

## 3. 身份与数据怎么流动

```text
用户消息 → 模型提出工具名和参数（不可信）
                              ↓
登录会话 → 后端绑定真实用户 → 安全网关
                              ↓
                  检查工具、参数和资源权限
                    ├─ 拒绝 → 记录审计 → 无正文
                    └─ 允许 → 读取密文并解密 → 记录审计 → 交付结果
```

信任边界就是“不可信输入必须经过检查，才能执行敏感操作”的位置。关键边界在工具提议进入网关时：模型不能给后端指定可信的 current_user_id（当前用户编号）。该值由登录身份提供，不从消息或 arguments（工具参数）中提取。

2026-09-09 补充：模型返回提议后、执行工具前，后端通过新的数据库会话重新检查原登录凭证是否有效、是否仍属于原用户。等待期间退出、过期或切换账户使原凭证失效时，旧请求不能继续读取正文。检查之后的所有并发撤销时序仍不在原子性保证范围内。修复与回归记录见 [代码安全检查](security-review.md)。

直接访问材料接口也经过同一网关。登录接口和管理员审计接口有各自的身份检查，不应笼统称为“所有 HTTP 请求都经过工具网关”。当前网关是同一个后端进程中的模块，不是独立部署的隔离服务。

模型收到当前消息和工具定义，不收到服务器会话或材料正文；后端直接根据网关结果组织最终回答，不将正文再次发送给模型。用户自己写进消息的敏感信息仍会发送给模型供应商，因此只能输入虚构数据。

## 4. 攻击与预期行为

| 攻击方式 | 应有的处理 | 验证重点 |
| --- | --- | --- |
| 消息中自称管理员、声称他人同意 | 不改变服务器登录身份；实际越权读取被拒绝 | 真实身份、实际工具与目标、拒绝结果 |
| 工具参数加入 role、user_id、跳过检查标记 | 额外字段不被接受 | 参数拒绝、没有读取正文 |
| 使用不存在的工具或伪装工具名 | 仅执行明确允许的两个工具 | 不动态执行输入指定的函数 |
| 把目标改为他人材料或不存在的编号 | 返回相同的拒绝原因 | 无正文，也不通过错误区分目标是否存在 |
| 只索取目标正文第一句话 | 未经授权仍不能交付正文 | 当前只支持整份读取，没有句子级工具 |
| 直接访问材料接口、绕开聊天页面 | 仍从会话取身份并经过网关 | 前端隐藏按钮不是权限防线 |
| 修改密文或把密文移到其他记录 | 解密验证失败，不返回部分正文 | 内容完整性与记录绑定 |
| 审计写入失败 | 不交付工具结果 | 不能出现已成功交付但未记录的正常路径 |

AES-256-GCM 是当前使用的加密方式，同时提供密文完整性校验。AAD 是参与校验但不加密的关联信息；本项目用它把密文绑定到材料编号和所有者。加密不替代授权，也不保护数据库中所有字段。合法旧密文被恢复到同一记录的回滚攻击不在当前防御承诺内。

## 5. 证据与结论分开

- 已有真实模型样例和已核对请求编号见 [安全验证记录](security-validation.md)。后续“虚假授权”和“只索取首句”由用户反馈拒绝且完成日志核对；本文没有收集它们的请求编号或原始日志，不把它们表述为新的独立核验记录。
- 新增的 14 个直接构造工具调用案例验证了拒绝、未查询密文、未调用解密，以及审计身份保持为 alice；该次网关测试总计 46 项通过。这不是模型话术成功率。
- 模型没有提出工具、选择了其他工具、或处理失败，均不能算作“网关拒绝了目标读取”。必须核对实际调用，不能只看回答语气或 HTTP 状态。
- 不宣称模型真的相信了伪造身份，也不宣称所有提示注入均被解决。提示注入就是试图用输入里的指令改变模型应有行为。

## 6. 目前不覆盖什么

- 服务器、数据库管理权限、加密密钥或管理员会话失窃；拥有这些能力的人可能绕过应用检查。
- 恶意管理员滥用其已有读取权限，以及合法接收者截图、复制、传播内容。
- 公网生产部署所需的完整防护，例如登录防爆破、跨进程费用控制、完备的可用性保护及密钥轮换。当前本机 HTTP 演示不能直接当作线上安全配置。

  登录已有本机单进程短期限制：同一用户名每 60 秒 5 次、全局 20 次；限制在密码校验之前执行，成功和失败都算，重启会清零。不保证抵御低速或分布式猜测，共享额度可能导致正常用户暂时无法登录。登录事件尚未加入材料审计。
- 防止所有费用或资源耗尽攻击；每次启动的模型调用上限不是持久化的账户预算。

  当前另有单进程内每用户最近 60 秒 5 次的短期限制，超限不调用模型；它只减缓消耗，不保证公平分配，不跨进程共享，也不替代登录限流。
- 不可篡改审计、日志完整性证明、完整事件覆盖及独立外部留存。
- 从网页、文件或检索材料中带入指令的间接提示注入；当前没有这些输入链路，也没有多步自主行动、任意网络访问或写入工具。
- 权限在并发执行期间变更的所有时序情况；当前测试不能证明权限撤销与正在执行的请求之间具有严格原子性。

## 7. 后续扩展的约束

新增工具、写操作、文件检索或多步调用之前，应重新审视本威胁模型。尤其不能把模型给出的用户身份接到可信身份参数上，也不能新增绕过授权直接读取正文的入口。写操作还需要单独设计业务修改与审计如何一起成功或一起失败。

一句话总结：在后端和真实会话可信的前提下，本项目把不可信的模型工具提议限制在登录用户已有的数据权限内；已验证的是具体实现路径和样例，而不是通用 AI 安全保证。
