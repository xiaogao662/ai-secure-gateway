# 本机 AES 密钥权限加固记录（2026-09-10）

已在本机对 `.secrets` 目录和其中的 `application.key` 执行权限收紧；未读取、重写、替换、删除密钥，也未操作加密数据库。

## 修改结果

- 所有者从创建文件的沙箱账户改为用户自己的 Windows 账户。
- 关闭从父目录继承访问权限，移除普通用户组及原沙箱主体的授权。
- 两个目标均仅保留用户本人、Windows SYSTEM 和内置管理员组的完全控制权限。
- 经用户普通权限进程复核：可以打开文件用于读取，检查后立即关闭，没有读取内容字节。
- 密钥文件大小和最后修改时间与修改前一致；未读取内容计算哈希，因此不声称做过内容摘要比对。

访问权限描述哪些账户可以访问文件；文件所有者还可以修改这些权限，因此本次同时处理了所有者。程序仍从原位置加载密钥，不需要更换密钥或重新初始化数据。应在用户正常终端中启动服务，不以原沙箱账户运行实际演示服务。

## 权限备份不是密钥备份

原权限记录位于 `.acl-backups/key-acl-20260910-01.xml`，结果记录在同目录的 `key-acl-20260910-01-result.xml`。它们只包含路径、账户标识和权限信息，不包含密钥内容；不能用来恢复丢失的密钥。

`.acl-backups/` 已加入 `.gitignore`，不应发布本机账户配置。原有 `.secrets/` 和数据库排除规则仍保留。备份恢复会重新放宽权限，除非排查确有需要，不要随意恢复。

本次使用 `scripts/protect_local_key.ps1`，需要事先确认目标账户标识并由用户批准 Windows 管理员操作。脚本验证目标不是链接，限定目录只有预期密钥文件，先备份、后修改、再复核；遇到错误会尝试回退，并在结果文件记录回退错误。其他电脑不能照抄本机账户标识；正常初始化也不会自动运行此脚本。

## 仍然存在的边界

这是文件权限加固，不是给密钥文件再加密：Base64 仍只是文本编码。以用户本人身份运行的恶意程序、管理员或被攻破的系统仍可能读取密钥；此前已经复制出去的内容不会被撤回。本次没有确认曾经泄露，也没有做密钥轮换。

项目父目录其他内容、数据库及备份位置未在本次收紧范围内；不承诺防止它们被删除或篡改。Windows 文件权限不替代操作系统防护、独立密钥备份或发布前文件检查。

后续只需用正常账户启动服务；不要为验证而把密钥粘贴到聊天、截图或日志。若密钥曾被公开，应另行设计密钥更换与已有密文迁移，不能直接覆盖文件。
